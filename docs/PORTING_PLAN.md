# RK3568 原生摄像头识别实施计划

## 范围

本仓库只负责从申请单进入画面到结构化字段发布。HID、SPI 屏幕、虚拟打印机、
MSC 和报告上传不在本次优化范围内。候选链路验证通过前不得覆盖现有服务。

## 已确认硬件基线

- ATK-DLRK3568，Debian 10，Linux 4.19.232，Python 3.7.3。
- IMX415 通过 MIPI CSI 接入 RKISP。
- `/dev/video0` 提供 `3840x2160 NV12`，实测连续取流约 30 FPS。
- 板端已有 RGA、RKNN Runtime、OpenCV 3.2 和 C++ 编译环境。
- RK3568 只有一个 NPU 核心，所有模型使用 Batch 1。

## 不可变行为

1. 多帧只用于检测纸张和判断稳定。
2. 稳定后只锁定最后一张稳定帧及其四角坐标。
3. 不采集备用帧，不选图，不重拍，不执行第二次 OCR。
4. 单帧质量、必填字段或置信度任一失败，本轮立即失败并等待移除纸张。
5. OCR 识别配置的大区域内全部文字，再按网页字段规则结构化；不得改成字段 ROI OCR。
6. 本轮结果保持锁定，连续 0.5 秒没有纸张后才能重新进入等待状态。

## 目标流水线

```text
IMX415 / RKISP 4K NV12
  -> V4L2 DMA-BUF 环形缓冲
  -> 空闲 5 FPS、候选 15 FPS 的 DocAligner 检测
  -> 两帧接近进入预稳定，四个不同帧且跨度 >= 180 ms 确认稳定
  -> 锁定最终稳定帧
  -> 最终帧质量检查
  -> RGA 裁纸张包围框并转换颜色
  -> CPU 单次组合透视：拉正、旋转、标准化、大区域裁剪
  -> PP-OCRv4 Mobile 文字检测与逐行识别
  -> 现有网页字段规则生成结构化字段
  -> 单次校验并发布成功或失败结果
```

## 模型与图像约束

- DocAligner：`256x256`，从锁定的 ONNX 转换为 RK3568 FP16 RKNN；保持现有 BGR
  通道顺序和 `0..1` 归一化。
- OCR 检测：保留 `480x480` 基准，另做 `384x480` 候选；一次 A/B 只改变输入尺寸。
- OCR 识别：`48x320`、FP16、Batch 1、单模型上下文。
- 不增加角度分类器、Batch 4、宽度分桶、第二次整页 OCR、切片 OCR 或低分区域重试。
- 标准长边保持 3200；识别区域沿用网页配置。组合透视直接生成最终区域，不生成
  中间整页 JPEG，识别主路径中不进行 JPEG 编解码或 Base64 传输。

## 验证门槛

- 固定私有测试图预热后至少 20 次，只记录平均、中位数、最小和最大值。
- 同图比较必须核对 SHA-256，性能日志不得包含 OCR 原文或患者字段值。
- 候选模型必须保持必填字段完整性和字段值一致性，才能替换基准。
- 现场至少 20 次完整放入/移除循环，覆盖移动、模糊、裁切、过曝、缺字段和低置信度。
- 连续取流至少 10 分钟，不得积压旧帧、泄漏缓冲区或重复启动同一张纸。
- 服务、模型和配置均保留一键回退；回退只用于部署版本，不得作为单次识别的自动重试。
